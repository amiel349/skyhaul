# 0013 · Least-privilege infrastructure

Status: accepted · 2026-11-24 · amends [0006](0006-command-delivery.md)

## Context

In M1 every service used the admin broker user and command senders declared the topology themselves (ADR 0006). M2 adds two long-running services on the fleet side, the API and the ingestor, that face users or untrusted drone data. A bug or a compromise in either should not let it reconfigure the broker, read other queues, or change the database schema. The ingestor also needs its own queue on `fleet.telemetry`, and that queue must not be able to slow down the simulator.

## Decision

- **`broker-init` owns the topology.** A one-shot (`flask skyhaul broker-init`, admin credentials, management HTTP API) creates the per-service users and permissions and declares everything through `skyhaul_contracts.topology` (`declare_topology` and `declare_ingestor_queue`). The API and the ingestor declare nothing and have no configure permission. Compose starts them only after `broker-init` has completed.
- **Per-service broker users:** `skyhaul_api` may write to `fleet.cmd` only and read nothing; `skyhaul_ingestor` may read `ingestor.telemetry` only and write nothing.
- **The simulator and the MCP server keep the admin broker user in M2** (test profile only) and keep declaring what they need; their own users come in M4. The MCP exception from ADR 0006 stands: it does not declare `drone_sim.cmd`.
- **Ingestor queue `ingestor.telemetry`:** quorum, durable, bound with `drone.*.*`, `x-single-active-consumer=true`, `x-delivery-limit=5`, dead-letters to `fleet.dlx`, `x-max-length=100000`, `x-max-length-bytes=6553600000`, and **`x-overflow=drop-head`**. A stopped ingestor must never push back on the simulator's publisher: with `reject-publish`, the publisher's nack retries would stall its outbox, and drone commands with it.
- **Database roles from an init script** (`deploy/postgres/initdb.d/10-roles.sh`, passwords from env): `skyhaul_owner` owns the schema and runs Alembic in a one-shot `migrate`; `skyhaul_api` and `skyhaul_ingestor` get only the grants they need (DML, no DDL; the ingestor may DELETE only from `telemetry`; `audit_log` is insert-only). No role is a superuser or has `CREATEROLE`.

## Consequences

- Queue arguments have one writer, so a service cannot fail its start with PRECONDITION_FAILED because an older version declared differently.
- A service started before `broker-init` finds no queue and fails fast instead of creating one with the wrong arguments.
- When the ingestor is down long enough to fill 100,000 messages, the oldest telemetry is lost first; a dropped ACK leaves its command `TIMED_OUT` for good (the drone's later telemetry still shows what it did).
- Init scripts run only on a fresh Postgres volume: existing local stacks need `make down -v` once.
- New secrets: `DB_OWNER_PASSWORD`, `DB_API_PASSWORD`, `DB_INGESTOR_PASSWORD`, `AMQP_API_PASSWORD`, `AMQP_INGESTOR_PASSWORD` (generated by `make env`, never committed).

## Alternatives considered

- Every service declares (the M1 rule): no ordering dependency at start, but every service needs configure permission on its queues.
- `reject-publish` on the ingestor queue: no silent telemetry loss, but a stopped ingestor would throttle the simulator and delay commands.
- Own broker users for the simulator and MCP server now: cleaner, but they run only in the test profile, and M4 reworks the test deployment anyway.
- Migrations at API start-up: no extra service, but the API would need DDL rights.
