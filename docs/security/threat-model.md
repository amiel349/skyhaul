# Threat model

Owner: security agent. Updated whenever a milestone adds a surface.

Skyhaul is a public repository. The main risks are leaked secrets, test evidence published with tokens in it, broken access control, and AI-specific abuse.

| Risk | Where | Mitigation | Milestone | Status |
|---|---|---|---|---|
| Committed secrets | .env, compose, CI config | Only `.env.example` in git; gitleaks in pre-commit and CI; GitHub secret scanning and push protection; `.env` blocked by a pre-commit hook | M0 | done |
| Default passwords | RabbitMQ, Postgres, Redis | No defaults: compose fails if a value is missing; `make env` generates random values | M0 | done |
| Secrets in images | Dockerfiles, registry | `.dockerignore` excludes `.env`; multi-stage builds; no secrets in ENV or build args; non-root user; Trivy scan | M0, M7 | partial |
| Personal data | git history, README | Commits use the GitHub noreply address; no phone or email in the repo | M0 | done |
| Employer material | The author's past and current employers | No code, names, documents or message names from either | always | ongoing |
| CI supply chain | Actions, dependencies | Actions pinned by SHA; `permissions: contents: read`; `persist-credentials: false`; no `pull_request_target`; lockfiles; Dependabot with a 7-day cooldown; pnpm `minimumReleaseAge` of 7 days | M0 | done |
| Agents reading secrets | Claude Code | Deny rules for `.env*`, keys and `secrets/` in `.claude/settings.json`; agent instructions | M0 | done |
| Exposed services | Local stack | Ports bound to 127.0.0.1 only | M0 | done |
| Malicious or malformed drone messages | `skyhaul_contracts.Codec`, every AMQP consumer and producer | The Codec is the only decode/encode path: 64 KiB (65,536 bytes) size check before parsing; strict UTF-8 and JSON (no NaN/Infinity, no duplicate keys); closed envelope; ASCII-only id and type patterns that are also the routing-key words; payloads validated strictly; error details name fields and kinds only, never input values (`<extra>` for unexpected keys); encode re-decodes its own output. Every decode failure is a `DecodeError` (deep nesting cannot escape as `RecursionError`) | M1 | done |
| Queue flooding and poison messages | `drone_sim.cmd`, `fleet.dlx` / `fleet.dead` | Queue arguments: quorum command queue with `x-delivery-limit=5` dead-letters messages that keep crashing a consumer; both queues bounded by count (10,000) and bytes (655,360,000), command queue rejects publishes when full, `fleet.dead` drops its oldest; `fleet.dead` keeps raw bodies and is inspected by hand only | M1 | done |
| Consumer message handling | Simulator consumer (and later the ingestor) | Undecodable bodies rejected without requeue to the DLX; routing-key `<id>` and `<TYPE>` checked against the envelope (and the version hint) before any NACK is sent; ack only after replies are in the outbox; a message the broker keeps nacking is retried a bounded number of times, then dropped and logged | M1 (#7) | done |
| Test backdoors in production: simulator control API | `drone-sim` control API (`/drones`, `/drones/{id}/faults`, `/reset`, `/stats`) | Compose `test` profile only, published on `127.0.0.1:8100` only; bearer token from env, at least 32 characters, no default, constant-time compare, checked before routing, never logged; request bodies validated and capped at 16 KiB; one validated model per fault kind with ranges; delayed replies capped at 1,000 per namespace and dropped on reset or when their drone is deleted; `/healthz` reveals only ok/degraded; no reset endpoint in the fleet API | M1 (#9) | done |
| Agent-controlled simulator (MCP server) | `skyhaul-sim` MCP server (`services/mcp_sim`), registered in `.mcp.json` | Local stdio process only, no network listener; secrets from the environment only (`.mcp.json` holds `${VAR:-}` references); token and broker password scrubbed from every tool result and error; control URL refused unless it is localhost; drives only the test simulator (no fleet API, so no confirmation step is needed: it is not the fleet commander); simulator text returned as JSON data and tool descriptions say it is never instructions; each call bounded in time (≤ 30 s telemetry, ≤ 60 s commands), messages kept (≤ 50) and deliveries read (≤ 10,000), with a broker prefetch of 100 | M1 (#11) | done |
| Test backdoors in production: fake LLM | `fake-llm` | Test compose profile only, internal network; never configured in the demo deployment | M5, M7 | planned |
| Broken access control | API endpoints, Socket.IO rooms | Single organization (ADR 0011), so access is by role only. Default deny: every route needs `@require` or `@public`, checked on the server before each request, with the user and role read from the database; a lower role gets 403 and is audited. Socket.IO `/fleet`: token only in the `auth` payload (a query-string token is refused), user checked active at connect, rooms assigned by the server from the role, no client event handlers, `command.updated` only to the dispatcher and admin rooms with the room taken from the event name (never the payload); a 30 s sweep disconnects expired tokens and disabled users | M2 | done |
| Password guessing | Login | argon2id; dummy-hash verify for unknown emails; rate limits per (ip, email) and per ip; every attempt in the audit log | M2 | done |
| Over-privileged services | RabbitMQ, Postgres, Redis | One-shot `broker-init` owns the topology and the users: `skyhaul_api` may only write to `fleet.cmd`, `skyhaul_ingestor` may only read `ingestor.telemetry`, neither has tags (no management or admin) and neither declares anything. Postgres roles from `deploy/postgres/initdb.d`: `skyhaul_owner` owns the schema and runs the migrations; `skyhaul_api` and `skyhaul_ingestor` get table grants only (no DDL, `audit_log` insert-only for the API); none is a superuser or may create roles or databases. Redis requires a password. The ingestor container is read-only, `cap_drop: ALL`, `no-new-privileges`, no published port | M2 | done |
| Admin broker user in the test profile | `drone-sim`, `skyhaul-sim` MCP server | Accepted for M2: both keep the admin broker user and declare what they need (ADR 0013). They run only in the compose `test` profile or as a local stdio process, never in the fleet stack; their own users come in M4 | M2 | accepted |
| Token theft by XSS | Browser | Access token in memory only (ADR 0015); refresh token only in an `HttpOnly` cookie, never in a JSON body or storage; CSP and the `v-html` ban. An XSS bug can act while the page is open but cannot carry a credential away (ADR 0018) | M3 | planned |
| CSRF on refresh and logout | `POST /auth/refresh`, `POST /auth/logout` | `SameSite=Strict` cookies plus an `X-CSRF-Token` header that must match the CSRF token bound to the refresh row; a custom header needs a CORS preflight the API never grants; same-origin only, no CORS (ADR 0018) | M3 | planned |
| Refresh token theft and replay | Cookie, database | 256-bit random token stored as SHA-256 only; rotated on every refresh; 7-day absolute family lifetime, not sliding; `Path=/api/v1/auth` so no other route ever sees it; never logged or audited | M3 | planned |
| Refresh token reuse | `POST /auth/refresh` | A used or revoked token presented again (after a 10 s grace window that answers 409 and issues nothing) revokes the whole family and writes `auth.refresh.reuse`; row lock (`SELECT ... FOR UPDATE`) serializes concurrent refreshes | M3 | planned |
| Weak cookie flags | Browser | `HttpOnly`, `SameSite=Strict`, narrow `Path`, `Max-Age` = remaining lifetime, fixed names; `Secure` on unless `AUTH_COOKIE_SECURE=false` (dev on http://localhost only); an API test checks every flag | M3 | planned |
| Brute force on refresh | `POST /auth/refresh` | 256-bit tokens make guessing infeasible; 30/min per ip limit; failures audited with a reason | M3 | planned |
| Session fixation | `POST /auth/login` | Login always starts a new family and revokes any refresh cookie sent with it; the CSRF token is new per login and per refresh | M3 | planned |
| Sessions outliving the user | Refresh, logout | Refresh refuses an inactive or deleted user and revokes the family; logout revokes the family on the server. "Log out everywhere" (revoke all families of a user, e.g. on password change) is not built yet | M3 | partial |
| Cross-sandbox access | Fleet API routes, Socket.IO `/fleet` | `namespace` column on drones, missions, alerts, commands; one choke point `scoped()` for every query; namespace taken from the visitor's sandbox row, not the token; foreign ids are 404, never 403; a route walk over the whole OpenAPI contract (sandbox A vs B) fails on a new unscoped path; socket rooms per namespace, room derived from the trusted event's drone id (ADR 0019) | M3b | planned |
| Visitor privilege escalation | Visitor role | No password, so no login path; dispatcher permissions inside the own namespace only, never `drone:admin`, `user:admin`, `audit:read`; drones registered by the `system:sandbox` actor; the database authorizes every request (ADR 0011, 0019) | M3b | planned |
| Simulator control API exposed through the demo | `drone-sim` control API, sandbox manager | The fleet API's sandbox manager is the only holder of `SIM_CONTROL_TOKEN`; control API on the internal network only in the demo profile, never published; visitor input never reaches it: counts and positions validated against fixed ranges and the demo area, faults are a fixed list mapped to fixed bodies | M3b, M7 | planned |
| Resource exhaustion by visitors | Sandbox start, commands, faults | 40 drones total under an advisory lock (busy page beyond); one active sandbox per visitor; per-IP daily caps on sessions and sandboxes; per-sandbox limits on commands, mission writes, faults and New simulation; 10-minute idle expiry; reaper for stuck and orphaned sandboxes; no Postgres telemetry for sandboxes | M3b | planned |
| Per-IP limits bypassed or misapplied | `client_ip()` | Until M7 the socket peer address; in M7 only the trusted tunnel's header, ignored from any other source | M3b, M7 | planned |
| Data left after a sandbox ends | Postgres, Redis, simulator | Stop resets the namespace (epoch drops late messages), deletes its rows and Redis keys; namespaces are never reused; visitor users pruned after their session expires | M3b | planned |
| Secrets in test evidence | Traces, videos, Allure, logs | Scrub auth headers, cookies and tokens before upload; throwaway users per run; reports published from main only | M4 | planned |
| Prompt injection | Drone names, alert text, chat | Tool results treated as data; tools run with the user's token; confirmation before moving drones; injection eval cases | M5 | planned |
| XSS from model output | Chat panel | DOMPurify; never `v-html` on raw text | M5 | planned |
| API key cost abuse | Demo, CI | PR CI uses the fake LLM; separate demo key with a spend limit; rate limits | M5, M7 | planned |
| AI PR reviewer abuse | `claude-review.yml` | Runs only on demand: a `/claude-review` comment from the owner, members or collaborators, or a manual dispatch; the workflow file always comes from `main`, so a PR can't change it; user text passed through `env` and the model name checked against an allowlist; contents read-only; tools limited to reading and commenting; PR text treated as data; advisory, not a required check | M0 | done |
| Triage agent leaks | Logs to Claude, PR comments | Redact before sending; agent has no tools; fixed code posts with a `pull-requests: write` token | M6 | planned |
